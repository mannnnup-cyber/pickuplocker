1. WHICH DIMEPAY FLOW IS ACTUALLY BEING USED?
──────────────────────────────────────────────
  @dimepay/web-sdk embedded widget — the initPayment() SDK flow.

  The app does NOT use POST /orders returning order_url, nor /payments/hosted-page,
  nor a standalone card-request/tokenization endpoint. Instead, the server generates
  a JWT signed with the Secret Key, bundles it into an SDKInitConfig object, and the
  frontend calls initPayment() from @dimepay/web-sdk@1.0.15 loaded via CDN
  (https://unpkg.com/@dimepay/web-sdk@1.0.15/dist/dimepay.es.js). The widget mounts
  into a <div id="dimepay-widget"> on the /pay/[reference] page.

  The chargeCardToken() function does make a server-to-server POST /api/v1/charges
  call, but this is for future/saved-card charges, not the primary checkout flow.


2. EXACT PRODUCTION API BASE URL AND ENDPOINT
──────────────────────────────────────────────
  SDK widget (client-side):     No direct API call — the widget handles its own
                                communication with DimePay
  Server-to-server charges:     POST https://api.dimepay.app/api/v1/charges
  Server-to-server authoriz.:   POST https://api.dimepay.app/api/v1/authorizations
  Capture:                      POST https://api.dimepay.app/api/v1/charges/{chargeId}/capture
  Webhook receiver:             POST https://pickupja.com/api/webhooks/dimepay

  NOTE: The same base URL (https://api.dimepay.app) is used for both sandbox and
  live. Environment is determined by the test: boolean flag in the SDK init config
  and by which credentials (sandbox vs live) are used.

6. WHICH CREDENTIAL SIGNS THE JWT?
───────────────────────────────────
  The Secret Key (prefixed sk_). The JWT is signed with:

    crypto.createHmac('sha256', config.secretKey)

  The Client ID is NOT used for signing — it is passed separately as clientId in
  the SDK init config.

11. IS iat ADDED AUTOMATICALLY BY THE JWT LIBRARY? SECONDS OR MILLISECONDS?
────────────────────────────────────────────────────────────────────────────
  iat is added MANUALLY (not by a JWT library). The code uses Node.js crypto
  directly to build the JWT — no JWT library is used.
